# ADR-0002: C# та ASP.NET Core як технологічний стек

Статус: прийнято

## Контекст

Після вибору Web-застосунку (ADR-0001) потрібно було визначити технології для серверної частини: автентифікація й профілі, пошук, бронювання, оплата, сповіщення. Уже в Sprint 1 команда має за два тижні отримати реєстрацію та вхід (FR-001), профілі (FR-002, FR-003) і CI-пайплайн зі збіркою та тестами на кожен push (FR-010), тому витрачати час на вивчення незнайомого стеку не можна.

Розробка коду запланована на другий семестр навчання, у якому розробник працює з C#. Для автентифікації, юніт-тестування й розгортання на staging потрібна зріла екосистема з готовими засобами.

Розглядалися варіанти: C# / ASP.NET Core, Python (Django/Flask), JavaScript (Node.js).

## Рішення

Серверну частину StudyBuddy розробляти мовою C# на фреймворку ASP.NET Core. Юніт-тести пишуться тією самою мовою, а .NET-артефакти збірки (`bin/`, `obj/`) виключені з репозиторію через `.gitignore`.

## Наслідки

**Плюси:**
- розробникам знайома мова, тому Sprint 1 реально вкластися в 23 години плану;
- ASP.NET Core має вбудовані засоби автентифікації та інструменти для юніт-тестування;
- один стек для всієї серверної частини спрощує CI та Code Review.

**Компроміси й обмеження:**
- проєкт прив'язаний до екосистеми .NET: staging-середовище має підтримувати .NET runtime, а нові учасники команди мусять знати C#;
- рішення стосується лише серверної частини: вибір СУБД і клієнтської частини ще не ухвалений і буде зафіксований окремими ADR (модель даних проєктується в задачі T-005);
- якщо вимоги замовника зміняться на користь іншої технології, перехід означатиме переписування вже написаного коду.
