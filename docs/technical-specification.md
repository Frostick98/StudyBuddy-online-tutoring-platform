# Технічне завдання: StudyBuddy

> Чернетка, зібрана з картки проєкту та плану спринтів Практичного заняття № 3.
> Замініть вмістом власного ТЗ з Практичного заняття № 2.

## 1. Загальні відомості

| Поле | Значення |
| --- | --- |
| Назва проєкту | StudyBuddy — платформа для онлайн-репетиторства |
| Тип системи | Web |
| Замовник | Освітній стартап StudyBuddy |
| Команда | 4 особи (Product Owner/аналітик, 2 розробники, QA-інженер) |
| Термін | 3 місяці (6 спринтів по 2 тижні) |

## 2. Призначення

Web-платформа, яка пов'язує учнів і репетиторів: пошук репетитора, бронювання
занять, онлайн-оплата та проведення занять з відеозв'язком або чатом.

## 3. Функціональні вимоги

| ID | Вимога |
| --- | --- |
| FR-001 | Реєстрація та вхід користувача (email + пароль) |
| FR-002 | Профіль репетитора (опис, предмети, ціна) |
| FR-003 | Профіль учня |
| FR-010 | CI-пайплайн: збірка та тести на кожен push |

Інші функціональні області за дорожньою картою: пошук репетиторів за предметом і
ціною, календар доступності, бронювання заняття, email-сповіщення, онлайн-оплата
та історія платежів, відеозв'язок/чат, відгуки та рейтинги.

## 4. Ризики щодо вимог

Вимоги можуть змінюватися: замовник уточнює функціонал за відгуками користувачів.
